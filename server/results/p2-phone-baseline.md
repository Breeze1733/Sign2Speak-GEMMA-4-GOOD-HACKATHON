- 三种方案在同一 `.bin` 上的词元序列与英文句子一致，说明 P2 的 118 点选取、编码、预处理、分类和投票与本地链路等价。
- 最终包复跑的 51 个 `m3_window_submitted.body_sha256` 与服务器 `p2.jsonl` 中的同名字段 **51/51 全部一致**，证明小端序、40 字节头、帧 stride、掩码位序和点选取在两端一致。
- P0 的 2.06 s 是手机 GPU；P1/P2 的 4.7–4.9 s 是服务器 CPU。按开题报告 §9.1 第 4 条，这是不同后端配置，不能当作纯划分收益。
- P2 相对 P1 的额外开销是高频窗口上传与远程分类：本次 5.0 MB 上行、单窗 P50 88 ms；收益是把手机上的 M3 计算移走。本次只有一个片段、一次运行，不足以给出统计结论。

## 口径与限制

- 单台手机、单个 16.27 s 片段、每个方案一次运行；不是 30 次重复，也不是完整 RTT/带宽矩阵。
- 没有做网络限速；Wi-Fi 链路速率不是实际吞吐或 RTT。
- 没有同步采集温度、功耗、峰值内存，不能据此说资源占用下降。
- 词元真值以 P0/P1 同片段输出为参照，未做逐词人工标注；“达到 50%”和“返回非空文本”不等于语义绝对正确。
- 计时口径：词元为首次检测到手→置信度达到 50%；组句为断句提交→生成函数返回文本，不含 3 s 自动断句等待、界面呈现和语音播放。
